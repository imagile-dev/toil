# The sample team

A web shop's software team, as data, that works on a fresh install with no connection and
no sync. `toil classify run`, `toil projects brief`, `toil projects pivot` and every Toil UI
screen can be tried on it, and a manager, a scrum master and a product owner can each
answer their questions from it (`docs/work-insights-seats.md`, M1 to P10, below). It is
for trying toil and for tests; it is not a template for anyone's real backlog.

Everything is generated by `src/core/sample/` as a pure function of one day, `--as-of`.
Every date is an offset from that day's UTC date, so the sample is always current, and
the same day gives the same bytes. The tracker records are in their native shapes
(`toil jira issue search --changelog`, `toil github pr get --include reviews,checks,commits,files`),
and the Open Work Items are what `toil util owi map` makes of them with the toil project's
own field settings, so nothing is written twice. Every host (`jira.imagile.dev`,
`github.imagile.dev`), name and address is a placeholder.

The figures below are for `--as-of 2026-11-10T08:00:00Z`, a Tuesday. They are computed from
the data (`toil sample team --part facts`), not typed. Dates move with the day: the
current sprint is on its seventh working day of ten when the day is a Tuesday, and on
another weekday the same calendar offsets land on another working day.

## Drop it in on a fresh install

Nothing here needs a connection, a config file or the network. Run these from any folder;
`--out` writes into the workspace, which is the folder you are in unless `--workspace` says
otherwise.

```bash
# The mix, with where each verdict came from
toil sample team | toil classify run

# Write the two files, then adopt the toil project by name
toil sample team --out sample
toil projects import sample/sample-team.project.json

# The briefing on the sample team, from the records
toil sample team | toil projects brief sample-team

# The same records from the file
toil classify run --file sample/sample-team.owi.json --toil-project sample-team

# Where the work goes: by team, then by category across the releases
toil sample team | toil projects pivot sample-team --split team
toil sample team | toil projects pivot sample-team --split category --across release

# The work mix by month, and what changed in it
toil sample team | toil classify mix --toil-project sample-team
toil sample team | toil projects pivot sample-team --measure throughput --split category --across resolved:month --share
```

The pivots need the toil project: it is what says who is on which team. Run on 10
November 2026 these gave Storefront 101, Platform 23 and no team 22; one notable change
for the releases ("2.4: 8 items were added after it started, 19% more than the 43 it
started with"); and a work mix of 55% feature, 35% keep the lights on and 10% unsure
over the items finished in the last 90 days.

`toil projects import` reports that the connections `sample-jira` and `sample-github` are
not set up; the sample does not read them. `toil sample team --part toil-project`, `--part jira`,
`--part prs` and `--part facts` print the other parts. `--out` never replaces a file, so
write to a new folder, or delete the files first, to generate again.

`toil sample team` is also the MCP tool `sample_team`, with the fields `asOf`, `part` and `out`.

## In Toil UI

The sample team is the first sample project in `toil-ui --sample`, and it is behind "Look
around with a sample team" on a fresh install, before any connection or Toil project
exists. It is generated for the day the sample is pinned to, so its dates stay in step
with each other. It exercises the Summary's Work mix, the six dashboards on Charts, the
Board's lanes, and People by team.

Toil UI's sample shows a slightly different mix from the commands above (59% feature,
31% keep the lights on, 10% unsure). That is by design: its sample comes with ten
corrections a person has already made, so the Classify view and its "How it's doing"
line have something to show, and a person's say changes an item's category.
