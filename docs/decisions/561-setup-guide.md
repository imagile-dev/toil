# Toil UI's setup guide, with the AI helper first (#561)

- **The AI helper moves to the front, and the wizard then explains itself with it.** The maintainer's call: set the helper up first so the wizard can use it as a guide, in a chat right beside the connection setup. The order is Welcome, AI helper (optional), Tools, Connections, Toil project, Jira fields, Finish, seven screens, with the progress counts following. Skipping the helper leaves every later screen as it was, plus one small line, "Set up an AI helper to get explanations here", with a button that goes to the helper step and, on Next, back to the step the person left. No screen is a wall.
- **The guide shows only when the helper can start.** A helper chosen in Settings or saved in the wizard, installed with its program found (`helperState` is `ready`, the Agent page's own test). In the preview, which has no helper to set up, the scripted guide counts as ready and answers the starter questions with canned text, labelled as a preview.
- **The guide is its own mode on the host, not an Ask question.** Ask refuses without a synced Toil project and fills its prompt from the cache. The guide (`AgentHost.guide`, `ui/server/agents/guide.ts`, `POST api/agent/guide`) takes the same adapter, caps, ledger and streamed answer, with its own prompt and its own tools, and needs no sync and no Toil project. It is not recorded in the worklog: the worklog is about work, and a setup question is about nothing in it. Its usage is in the usage ledger under "(setup guide)", so the caps still count it.
- **What it is told is built on the server from three sources and no others.** The wizard's whitelisted state (`guideStateOf`, `src/guide.ts`: step, tools ticked, the tool being linked, `deployment`, the composed address, the Toil project's name), `connections list` run read-only by the host (name, tool, address, deployment, writes, and the token badge Settings shows, saved or from an environment variable or missing, never a value), and toil's skill pages. Never from the page's contents. The connection form reports its non-secret `submission` through an `onDraft` callback, and the wizard reads two keys from it; the masked boxes are in a different state the wizard never holds. The address is cleaned to a plain address (no login, query or fragment) and dropped if it looks like a secret.
- **The docs come from the skill pages already embedded for the MCP resources** (`src/skill-pages.generated.ts`). The guide reads the setup pages and the pages of the tools the person chose (every tool's, before any is chosen) through `docs_read`, cut at 24,000 characters and saying so; `connection_scopes` reads each area's declared scopes from the registry the settings pages already use. This puts the skill pages in the server bundle, about 220 KB, which the maintainer can overturn by serving them from toil at run time once toil exports them.
- **Its tools are reads.** The docs, the scopes, and, only once a Toil project exists, toil's live read commands for it (the same `liveTools` Ask has). It has no write tool and no way to run a command.
- **A suggested change is a card with Run this, through the wizard's own call.** The guide may suggest only `connections add` (with plain `--set key=value` settings, which takes no secret), `projects init`, `projects add-repo` and `projects link`, the table `GUIDE_COMMANDS`. The server leaves out any suggestion outside the table, with an unknown or missing field, or with a value that looks like a token; the page checks the same function again before showing a button and again before running. Run this is `config.run`, the allowlist Settings uses, so the connection's own write gate and the audit log are unchanged. It does not use Ask's proposal card, which says `--allow-write` and holds tracker changes; these are local setup commands.
- **Secrets never reach it, and the layers are the same function.** `looksLikeSecret` (`src/guide.ts`) runs toil's `checkSecret()` on the message, each word and each pair of words (which finds a `Bearer ` or `TOKEN=` wrapper), then the usual credential prefixes (`ghp_`, `github_pat_`, `ATATT`, `glpat-`, `xox`, `AKIA`), a JWT, a private key header, an address with a login in it, `password:` or `token=` followed by a value that has a digit or is long, and one long key-shaped word. It runs in the panel before anything is stored, in the page's client (`httpAgent.guide`) before a request is made, at the route before the body's other fields are read, and in the host before the connection list, the agent, the ledger or the worklog is touched. A refused message is cleared from the box, never put in the chat, the ledger, the audit log or a response, and not logged. The cost is a false refusal now and then (a long identifier); the notice says where a token goes instead, and the person can rephrase.
- **The guide's own answer is checked once more.** An answer that contains something shaped like a token is replaced by a notice that it was held back. It can't come from the person, but a model can repeat what a docs page shows.
- **Narrow screens fold the guide.** Below 1000px it is a `<details>` named "Ask the guide", closed, below the step; from 1000px it is a second column. The chat lives in the component, so it survives the fold and the move to the next step, and nothing is kept in browser storage or after the tab closes.
- **Plain words in the screens this touches.** `ToilProjectSetup` says tool (not area), AI helper (not agent) and accounts (not identities) in its headings, buttons and labels; the wizard's connection list says "changes on/off" with "In toil: writes" in a hover. The Settings forms are not given hovers for every renamed label: `ChangeForm` takes a title and a submit label as text, and a hover would need a prop on every form. The renamed words are the ones toil's contract names in its commands, so the command line shown under each form still says `area`.
- **Not done:** the hover for the renamed labels on `ChangeForm` titles and submit buttons, per-step addresses (`#/setup/<step>`), and saving the guide's chat.
