# Security fixes for open dependency findings (#586)

- Bumped only versions at least 14 days old: `@modelcontextprotocol/sdk` 1.32.2 (21 days; 1.32.0 was the first patched), `zod` 4.6.7, `vitest` 4.1.12, Toil UI's `vite` 8.3.5 (8.3.3 was the first patched, 8.3.8 is two days old), the function's `@azure/identity` 4.14.1. The newest patched release was not taken when a slightly older one fixes the same advisories, so the pins stay clear of the 14-day line.
- Transitive fixes (`body-parser` 2.4.0, `fast-uri` 3.1.9, `@azure/msal-node` 7.1.2, the site's `vite` 6.4.5) are lockfile-only. `npm update` and `npm install` pick the newest version that fits a range, which pulled in releases under 14 days old (`@azure/msal-node` 7.2.2, `semver` 7.8.6), so they were resolved with a temporary `overrides` entry that was then removed, and `semver` was put back by hand to its old entry. No `overrides` remain in any `package.json`.
- Waiting for the 14-day rule: `hono` 4.13.16 (eligible 2026-11-15), `@hono/node-server` 2.1.6 (2026-11-16), `fast-xml-parser` 5.12.0 in the function (2026-11-17). All three are dev tooling or low severity, so no stopgap was added.
- Not bumped, left as questions for the maintainer because the fix changes more than a lockfile: Astro (two major versions, and its resolution needs releases under 14 days old until about 2026-11-25), `minimatch` and `esbuild` (their parents pin a range that excludes the patched release), and the Node floor.
- Toil UI's Install tested-versions pin moves with the root `zod` (`ui/test/install.test.ts` holds them equal): the Install screen now shows `zod@4.6.7` beside Claude's SDK instead of `zod@4.6.5`. The install is still exact, still under `--before`, and 4.6.7 is a patch release past the memory-exhaustion advisory. It is the one change here a Toil UI user can see.
- No other source changes: code scanning is not enabled on the repository, so there were no findings to fix, and the shipped advisories are in libraries whose vulnerable paths (HTTP transports, OAuth client) toil does not use, apart from input validation, which the bump covers.
