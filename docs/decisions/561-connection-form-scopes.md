# Connection form, scopes and the existing-connection check (#561)

Decisions made by default in this slice, for the maintainer to keep or overturn.

- **One metadata mechanism for every form choice.** `defineArea({ choices })` turns a setting into radio buttons: GitHub's address (GitHub.com or Enterprise Server), the deployment of Jira, Confluence, Bitbucket and Azure DevOps (a *required* radio, nothing preselected), and the address each deployment composes (Cloud: a site or organization name; Data Center: a URL; Bitbucket Cloud: the fixed API root). `appliesTo` and the keys each `variants` entry already `requires` or `uses` decide required, optional or hidden. It is a presentation only: the schema still validates, `toil connections add` still takes any value, and the registry's `connection[]` gains optional fields (additive, not a contract change).
- **The rules are pure functions in `src/core/connection-form.ts`**, read by Settings and the wizard alike, with `ui/test/connection-form.test.ts` table-driving them for the four deployment areas and GitHub, and comparing each area's `variants` to the CLI's own schema so the form and `connections add` cannot drift. Save is `aria-disabled` rather than `disabled` when something is missing, so pressing it can move focus to the first missing field and announce why.
- **Other areas.** Only the four variants areas and GitHub got choices; no other area has a cloud/self-hosted address pattern that is identical enough to be trivially safe (`db` has variants keyed on a typed engine, which the form treats as typed text and gates nothing on).
- **Scopes: GitHub only.** `defineArea({ scopes })` and `toil connections scopes` are generic, but only GitHub's credentials have named scopes whose commands were derived from the requests they send. Jira, Confluence, Bitbucket and Azure DevOps were left alone: their scopes were not derived from the commands in this slice. The fine-grained permission names (Pull requests, Contents, Issues, Checks, Commit statuses, Projects (organization), Administration) come from GitHub's documented REST permissions and have not been verified against a live token; the merge commands list Contents as well as Pull requests as a deliberate superset.
- **The token-type radio is page state only.** toil sends both kinds as `Authorization: Bearer <token>` and nothing rejects either shape, so no key was added; the radio changes the help and the scopes shown, and a pasted token of the other kind draws an advisory Switch.
- **`checkSecret` was extended, not duplicated:** a pasted `NAME=value` or `export NAME=value` is found as a wrapper and asked about, as `Bearer ` and quotes already are.
- **Existing connections are found through `connections list`**, which reports where each value lives and never the value. The wizard defaults to "Use it" when exactly one good connection exists, and Replace needs a tick and names what it overwrites; an environment-defined connection is listed read-only. An unreadable list is shown as a dash, not as none.
- **The Toil project step** lists folders or addresses, runs `projects init` then one `projects add-repo` each, shows the one file it writes before the button and what was saved after, and never passes `--shared`.
- **Not done:** the page cannot see the disk, so a folder is never reported as existing or as a git repository, and the first row is not prefilled with the folder Toil UI was started in.
