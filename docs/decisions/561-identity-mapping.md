# Identity mapping: per-area person flags, `projects people suggest | save`, and Map in Toil UI (#561)

- **What:** `toil projects person` gains `--github`, `--jira`, `--ado` and `--bitbucket`, each the same as `--id <area>=<identity>`. **Why:** the four work-tracking areas are the ones a person is mapped in, and a flag per area is what the issue asked for. They go through the same checks as `--id` (credential-shaped values refused, one account one person). **Where:** `src/projects/build.ts`.
- **What:** `toil projects people suggest` reads OWI records (the input `projects brief` takes) rather than calling a service. **Why:** principle 3: one command, one source; the caller reads GitHub, Jira, Azure DevOps or Bitbucket with that area's own command, maps it with `util owi map`, and pipes it in. It is read only and maps nothing. **Where:** `src/projects/build.ts`, `src/core/people-match.ts`.
- **What:** matching is email (the person's email, or an identity they already hold such as an Azure DevOps email), then display name in any word order, then a login that reads as the name (`pexample`, `pat.example`). An account that fits two people, or fits a person who already has an identity in that area, suggests nothing and says why. **Why:** a wrong suggestion is worse than none. Trigram similarity was left out: it needs a threshold that nobody could defend. **Where:** `src/core/people-match.ts`.
- **What:** `toil projects people save` merges the people into `<repo>/.toil/projects/<name>.json` (a missing file is created as `projects export` would, with the same MCP refusal for writes bindings). A person the file lists differently is refused unless `--replace`; people only the file lists are kept. **Why:** a checked-in file belongs to the team, so saving must not drop a teammate's entry or silently overwrite one. It is a file under the repository, so it works for any host. It never stages or commits. **Where:** `src/projects/build.ts`.
- **What:** `--repo` defaults to the working folder, which must be a repository's root. In Toil UI that is the folder the server was started in; the page says so. **Skipped:** choosing among the Toil project's own repos in the page, because their local paths may not exist on this machine.
- **What:** Toil UI keeps its own email-based "Possible matches" panel and adds Map, which uses the core matcher for one account. **Why:** the panel is built on the page's already-loaded data and changing it was out of scope.
- **Not a breaking change:** every addition is a new command or flag; no path, flag, envelope field or error code changed (principle 7).
