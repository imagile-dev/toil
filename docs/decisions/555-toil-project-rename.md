# Rename dossier to toil project (#555)

- **The term is "toil project", never a bare "project".** A bare `project` is Jira's, Azure DevOps's and SonarQube's `--project`. The CLI path and folder use the plural `projects`, the flag is `--toil-project`, the MCP field is `toilProject`, identifiers are `toilProject` / `ToilProject` / `toil-project`. Principle 10 now says so.
- **The old MCP tools and resources are dropped outright** (the maintainer's call, 2026-11-04): `dossiers_*`, `<area>_check_dossier`, `toil://dossiers*` and the `dossier` field no longer exist over MCP or the API. Principle 7 allows this as a declared breaking change; `contractVersion` goes from 2 to 3.
- **Everything a person types in a terminal or keeps on disk still works for one beta, with a warning:** `toil dossiers …` and `<area> check-dossier` (hidden `deprecatedPaths`, not `aliases`, so the contract and site don't list them), `--dossier`, `TOIL_DOSSIER` and `TOIL_DOSSIER_PATHS` (the new name wins when both are set), the `dossierPaths` config key, and the `dossiers/` folders. Warnings: `TOIL_PROJECT_DEPRECATED_NAME`, `CONFIG_RENAMED_KEY`, `TOIL_PROJECT_OLD_FOLDER`. Why: a script or a profile that names the old thing should say what to change, not fail.
- **Config version 4** renames `dossierPaths` to `projectPaths`. Both key names stay reserved. `toil connections migrate` writes version 4, and an older toil or Toil UI cannot read it afterwards.
- **`toil projects migrate` is CLI-only** and moves `~/.toil/dossiers/*.json` into `~/.toil/projects/` on a typed `yes` or `--yes`. It never overwrites and leaves everything else alone. A repo's checked-in `.toil/dossiers/` is not moved: the person runs `git mv`, because those files belong to the repository.
- **Source values and `data` keys changed with the term:** `'dossier'` is `'toil-project'` in `meta.context` sources and `meta.transition.resolvedBy`; `projects list` returns `toilProjects`, `projects show` returns `toilProject`; bound ids are `projects.*`; warning codes `DOSSIER_*` are `TOIL_PROJECT_*`.
- **Toil UI:** routes `#/dossier/<name>/…` are `#/project/<name>/…` and `#/settings/projects`; the old hashes are upgraded in place so bookmarks still open. The SQLite cache gets migration 6 (rename tables and columns, rewrite stored JSON keys, empty the response cache so the next sync re-reads). The remembered-agent file is read once from its old name. Plain-words no longer swaps the term, since the plain and toil terms now coincide.
- **`ui/` still pins toil beta.3,** whose envelope types name the old source value, so `ui/server/main.ts` and `ui/test/github-repo.test.ts` cast `execute` to the app's own type. The casts come out when the pin moves with the release.
- **Left as written:** `docs/decisions/*`, `AGENT_DECISIONS.md` and the changelogs keep the old word, since they record what was decided then. `site/src/data/welcome.json` is a recorded terminal session and still shows the old menu; it needs re-recording.
- **`skills/toil/upgrading.md`** tells an agent how to convert each kind of thing, on the person's approval and never by hand-editing `~/.toil/config.json`: the config file, the folders, env vars, scripts and CI, MCP settings and allowed-tools lists, and warning codes.
- **Review round 1.** `skills/toil/upgrading.md` now describes the errors an old MCP call gets as they are: the SDK's `-32602 Unknown tool: dossiers_list`, and `INVALID_INPUT` for a `dossier` field, whose fix now names `toilProject` (`RENAMED_FIELDS` in `src/core/run.ts`, one entry, there for any later rename). A retired group such as `toil dossiers` lists its commands in `--help`, each saying what replaced it, and stays out of the root help.
