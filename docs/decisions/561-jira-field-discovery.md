# Jira custom-field discovery (#561)

- **`jira field discover` is one read command for both deployments,** folded by `area.byDeployment` from two thin commands that share `src/areas/jira/discover.ts` and differ only in four reads (field list, a project's issue types, a JQL sample, one issue). It is `writes: false`, so it needs no `--allow-write` and is served over MCP. Additive: the contract records none of it, so no divergence entry.
- **It samples; it does not scan.** `--project` reads the most recently updated issue of each issue type (`--per-type` 1 to 3, `--limit` at most 12 types), `--issue` reads up to 20 named issues. A project costs 2 requests plus one search per type, 14 at most with the defaults. Types beyond `--limit` are named in a `JIRA_DISCOVER_TRUNCATED` warning. The JQL uses the type's id, not its name, so a quote in a name cannot change the query.
- **Unknown is not none (principle 12).** A type with no issue to read has `sampled: null`, `status: "no-sample"` and `fields: null`; a type that was read and holds no custom value has `fields: []`. The screen says "No Epic issue was found to read" for the first and "No custom field holds a value on KEY" for the second.
- **Guesses say how sure they are and why.** `owi` is `high` only for Jira Software's Sprint schema (`gh-sprint`), a numeric field named exactly Story Points or Story point estimate, and Jira's own Team schema; a likely name (a number mentioning points, a date named Due date or Target end, a custom Team, Priority or Type) is `medium`; anything else is `null`. Only high starts ticked in Toil UI. A person is never shown in a preview (`(a person)`), nor rich text (`(rich text)`), and a preview is at most 80 characters with email addresses replaced.
- **Applying is `projects field`, shown and never run by discover.** For a field that is an OWI field the commands are two: the friendly alias, then the OWI key (`estimate`, `iteration`, ...) pointed at the same id with `--replace`, the flag Settings' "Point an existing alias at this field" box sets. The pure helper is `src/core/field-discovery.ts`, which Toil UI imports so the table and the terminal agree.
- **Toil UI calls the read through `CONFIG_READS`, not `ui/server/reads.ts`.** The setup wizard and Settings only hold the `ConfigApi`, whose server path is `/api/config`; its read list already runs read-only and is held to the registry by `test/config.test.ts`. `READ_COMMANDS` belongs to the dashboards' `execute` client, which these pages don't have. The step is optional and skippable (`fields`, between the Toil project and the AI helper), and with no Jira link or no Toil project it says so and offers nothing to run.
- **Found, not fixed: naming a field in a Toil project does not make `jira issue search` return it.** Search returns the standard fields plus the connection's registered `customFields`; a Toil project's aliases (and its `estimate` / `iteration` pointers) are read only by `--field` on create and update and by `mapOwi`, which can only point at a field the record holds. Checked on the Cloud sandbox: with no `customFields` registered a default search returns ten standard fields, and `--fields summary,customfield_10020,customfield_10016` returns both. So after naming, Toil UI's cards still show no sprint or points until search is asked for them. The follow-up is for search to add the field ids a Toil project's OWI pointers name to its default fields (a change to what a search returns, so a declared, additive one), or for the UI's load to pass them in `--fields`. Left alone here for the reason the sprint decisions record: it changes what every caller receives.
