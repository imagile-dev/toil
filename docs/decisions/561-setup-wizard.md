# Toil UI's setup wizard, slice 1 (#561)

- **The wizard takes connection secrets in the web UI, by the path Settings already uses.** The maintainer's call for this slice (it supersedes the first brief's "only in your own terminal"): a secret must never pass through an AI agent, but a deterministic call from the page is fine. The connect step embeds Settings' own `NewConnectionForm`, so a masked field per secret key is checked by `checkSecret` (`src/core/secret-input.ts`) and sent in one `/api/config` call as `secrets`, which the server hands to toil's `connections add` as the call's `person`. toil stores it in the OS credential store; nothing is stored by the page, nothing goes in a URL, and the fields are cleared before the call returns. No new endpoint, no second place a secret is typed.
- **Why reuse and not a wizard-only form.** A second form would be a second place a secret is typed, with its own paste checks to keep in step. `ui/test/config.test.ts` already sweeps every response, the config file, the audit log and the server's output for each secret it sends through `connections add` and `connections login`; the wizard rides that path, and `ui/test/setup-wizard.test.tsx` adds the page's side (the secret is in `secrets` only, not in `input` or `answers`, and not in the page afterwards, and the wizard has no import of the chat or the agent).
- **Writes stay off.** The new connection is made by `connections add`, which starts writes off; the wizard says so on the screen and never calls `connections writes`. Turning writes on remains Settings' typed-name form.
- **A terminal alternative is one step further in.** "Prefer to type it on a terminal?" shows `toil connections add <name> --area <area>` with Copy, and the test step names `toil connections login <name>`.
- **Progress is page state only.** No config key was added. Closing the tab loses the ticked tools and the step; connections and Toil projects already saved stay, and the tools step marks an area that already has a connection.
- **Common tools first.** GitHub, Jira, Azure DevOps, Bitbucket, Confluence and SonarQube lead the list; every other area whose connection the registry describes is under "More tools". An area whose connection fields the server doesn't describe is left out, as Settings does.
- **The wizard links the connections it set up to the Toil project it creates** with `projects link` (and adds an optional repository with `projects add-repo`), because an empty Toil project has nothing to read. A link toil refuses (a connection with writes on) is shown as toil's own error.
- **The helper step reuses the Agent page's Install dialog and Save.** It adds only the plain-words explanation and Skip. In the preview it shows the sample status and installs nothing.
- **Not done in this slice:** a per-step address (`#/setup/<step>`) and remembering progress across a reload.
