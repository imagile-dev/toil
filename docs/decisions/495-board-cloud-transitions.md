# Board moves on Cloud items use the Cloud area's own transition command (#495)

- **A board move on an `ado-cloud` item is proposed as `ado-cloud work-item transition --state …`**, the same as `ado`. This supersedes the entry in `AGENT_DECISIONS.md` (the `ado-cloud` seed, #319) that proposed `ado-cloud work-item update --field System.State=…` because the area had no transition command. It has one since #322, and that command shipped in toil 0.1.0-beta.1, the toil Toil UI pins. Where: `ui/src/model/board.ts`, `proposeMove`.
- **A board move on a `jira-cloud` item is proposed as `jira-cloud issue transition`, and its hint is `jira-cloud issue transitions`.** Before, both named the Data Center commands, which would have run against the wrong connection. Each Data Center and Cloud pair names its commands alike, so the item's own area fills in the path. Where: the same function. #495 later folds the `-cloud` areas into one area per product, and these lines then name `jira` and `ado` with no further change.
