# The toil skill tells agents how to handle an upgrade (#495)

- **The changelog page is generated into the bundle, not committed.** `scripts/gen-areas.mjs` builds `changelog.md` from `CHANGELOG.md` and adds it to `skillFiles`, next to the files of `skills/toil/`. A committed copy would be a second changelog that the release PR would have to regenerate; release-please already writes `CHANGELOG.md` there, so the embedded page always matches the version being released. The cost: a clone reads `CHANGELOG.md` itself, and `toil://skill/changelog` and the installed skill folder carry the page.
- **Cap: the newest 5 released versions, within 40,000 bytes, breaking changes and features only.** The newest version is always kept; older ones stop at whichever limit comes first. The page says the cap. Bug fixes stay in `CHANGELOG.md`: an agent converting config needs the migration notes, which sit under BREAKING CHANGES.
- **The page is reachable by `changelog.md` beside the skill and `toil://skill/changelog`; `toil skill show` is unchanged.** Its input stays empty, since adding a page argument would change a command contract for what a file read already does. The MCP server now lists `upgrading` and `changelog` whatever `--areas` says, because they belong to no area.
- **`upgrading.md` is not an area page**, so it is in the test's list of general files and has its own docs page, `/docs/upgrading/`, in the Agents group of the docs path.
- **Approval rules the page gives the agent.** It never hand-edits `~/.toil/config.json`, never prints or moves a secret value, and never adds a connection, turns `writes` on or changes a credential. Persisting a migrated config is `toil connections default <name>` on the connection that is already the default, run only on the user's yes, with the warning that an older toil and a Toil UI pinned to one can no longer read the file. Env vars, CI files, dossiers in a repository, scripts and MCP entries are changed only with approval; a dossier in `~/.toil/dossiers/` may be edited with approval, one in a repository is proposed to its owners.
- **Retired names are listed in the page and held to `RENAMED_AREAS` by a test**, as is every code the page names (it must exist in `src/`, except the three renamed `ADO_CLOUD_*` warning codes, which must not).
