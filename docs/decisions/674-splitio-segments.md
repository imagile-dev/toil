# Split.IO segments, flag sets, traffic types and rollout statuses (#674)

- **`rule-based-segment update` sends only `rules`, `excludedKeys` and `excludedSegments` from the file**, plus the name, as `flag update`'s siblings copy only the writable fields: `get`'s output also carries `title` and `comment`.
- **Every new write is a change request**, as every flag write already is. Split documents a `segment` change request (`CREATE` adds keys, `ARCHIVE` removes them) and a `ruleBasedSegment` one (`UPDATE`) on Submit Change Request. Split also has direct key-upload and rule endpoints, which toil leaves unused. That keeps the area's rule that toil never changes anything in Split itself.
- **Segment writes take no `--rollout-status`.** A rollout status belongs to a flag, and Split's segment examples send none. `segmentCrFields` is `crFields` without it.
- **Keys come from `--key` (repeatable) and `--input-file`, together and each once.** The file is one key per line, or JSON: an array of strings, `{ keys }`, or a whole toil envelope around either, so stdout from `segment keys` (with or without `--select keys`) pipes in. Other JSON is refused, never read line by line. More than 10,000 keys (Split's limit for one call) is `INVALID_INPUT` before anything is sent, rather than one request Split would refuse.
- **`segment keys` returns plain strings** (`["user-1"]`), not Split's `[{ "key": "user-1" }]`, so a page pipes straight into `add-keys` or `remove-keys`. `totalCount` is Split's `count`, which its reference example shows as the segment's total (200 beside five keys), not the page's length. That reading is an assumption until a live run.
- **List commands read one page and say so**, as `flag list` and `change-request list` do: offset lists (`segment list`, `segment keys`) take `--limit` and `--offset` and return `totalCount`; marker lists (`flag-set list`, `attribute list`) take `--limit` and `--after`, set `meta.page`, and return `totalCount: null`, since Split reports no total. Large and rule-based segment lists take no paging parameters in the reference, so they return what Split sends.
- **A list Split answers in an unexpected shape is an `HTTP` error, never an empty list** (`itemsOf` in `client.ts`, principle 12). Split answers lists as a bare array, `{ objects }` or `{ data }`, and the reference schemas for large-segment lists are ambiguous, so all three are read.
- **An empty marker is the last page.** Split's flag-set example sends `""` for both markers; toil reports that as `null`.
- **`attribute list` always sends `Paginate=true`**, with the capital P the reference spells. The unpaged form is deprecated, and `searchPrefix` works only with paging. The parameter's letter case is an assumption until a live run.
- **Flag sets use `/internal/api/v3`** (`splitV3` in `client.ts`). Everything else stays on v2.
- **`flag list --name` reads every page**, 50 at a time, keeping names that contain the text in any letter case (#671, the maintainer's call for client-side). It adds `searched` and `complete` (`null` when Split gave no total). It refuses `--limit` and `--offset`, and a timeout is an error, never a partial list. `--tag` and `--flag-set` still go to Split on every page.
- **`flag list --tag` is repeatable**, sent as one `tag` parameter each, as the reference documents.
- **Left out:** deletes, large-segment key uploads (a PUT to a pre-signed URL on another host, which `restRequest` refuses by design), emptying a large segment, API keys, users and groups, identities, events, and creating workspaces, environments, segments or flag sets.
- **Not changed here:** `flag list --flag-set` still sends the undocumented `flagSetName` (#79 item 14). The documented filter is `flag_sets` (flag set IDs) on the per-environment definitions endpoint. Changing it changes what an existing flag sends, so it waits for a live check or the maintainer.
- **No contract entries for the new commands.** The contract records what callers already relied on, and the new commands and flags are additive. `test/contract.test.ts` still holds the existing `flag list` row.
