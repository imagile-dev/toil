# The root Vitest suite runs faster without dropping a check (#579)

- **Parity is eight files, not one** (`test/parity/shard-0.test.ts` to `shard-7.test.ts`, one shared `test/parity/suite.ts`). The 4,700-test file set the wall time of the whole suite. Each shard claims units of work by counting them in a fixed order, so no list of areas or commands exists and areas still register by existing. A unit is a suite's own checks, one command's checks, or one cross-area check. A traced suite (`db`, `util`) stays in one shard, because its last check reads what every example logged.
- **`--select` and `--output-format toon` with `--summary-file` run once per area, on its first command** (`test/parity/suite.ts`). They test core machinery that is the same for every command, and CLAUDE.md's list of parity checks never named them. They stay in the suite and still go through both doors. What is lost is catching a command that breaks one of them alone; the per-command select and output suites in `test/select.test.ts` and `test/output.test.ts` still run the machinery on its own terms. This is the one place a check got narrower; the maintainer asked for it.
- **A toil-project test disk resets by difference.** `toilProjectDisk().reset()` used to delete and rewrite the whole temp tree twice per example, which made the toil projects commands about five times slower per test than any area on Windows. It now removes what a run added, and rewrites a seeded file only if it no longer reads as seeded, so the disk ends up as `seed()` left it.
- **The triage safety list names the folder `test/parity/`**, not one file, so a shard or the suite is flagged for a human the way `test/parity.test.ts` was (principle 2).
- **Wall-clock bounds got room, and keep their meaning.** Linear-time guards in `test/audit.test.ts`, `test/owi.test.ts`, `test/owi-similar.test.ts`, `src/core/query/query.test.ts` and `src/areas/util/size-imports.test.ts` now allow seconds where linear takes milliseconds and the quadratic they guard against took six to seventeen. The size-imports ratio test takes the best of three on each side, so one garbage collection cannot decide it.
