# Tooltips with Read more links, and edit links to configuration (#346)

- **The (i) is React Aria's Tooltip on hover and focus, and a popover with the Read more link on press.** A tooltip closes the moment focus or the pointer leaves its trigger, so a link inside one can be seen but never reached by keyboard or touch (WCAG 2.1.1), and touch has no hover at all. The tooltip shows the topic's sentences; pressing the (i) opens the same sentences in a React Aria Popover and Dialog with the link, the way the Ask strip's (i) already works. `ui/src/components/help.tsx`.
- **The (i) opens from a small button only, not from focusing a term.** Making terms focusable would add tab stops inside sentences and headings. Every term with a topic has its (i) beside it.
- **One help-topic table, `ui/src/help.ts`, plain data with no imports.** Each topic is a title, one or two sentences, a docs page and a heading id. The site's build reads the same file as it is (Node strips the types), so the table is written once.
- **Two link checks.** `ui/test/help.test.tsx` maps each topic's page to the markdown it renders and finds the anchor among that file's headings, slugged as github-slugger does; it runs in every `npm test`. `site/scripts/check-help-links.mjs` runs after `astro build` and looks for each id in the HTML that was built, which catches any slugging difference the test's copy of the rule misses. The pages workflow runs it on every PR that touches `ui/` or `site/`.
- **Insights got a docs section** (`ui/README.md`, **Insights**) for the insights topic to link to, since nothing documented what each chip means. One (i) on **Needs attention** explains insights rather than one per chip: a focusable control on every chip would add three tab stops to every board card. The board's chips keep their titles.
- **Themed microcopy stays on the page.** The dossier list's lede and the dashboard's panel notes are a theme's words (#283), so they stay, with an (i) after them; untouched themed text keeps every theme's voice working.
- **What a form will do before it runs stays on the page.** The settings forms' explanations (what Remove deletes, what a login stores) are what a person needs to act, so they aren't moved. What moved: the views' ledes past their first sentence, the Settings intro and each page's second sentence, the explanation paragraphs on Connections, Dossiers, Set up this repo, General (bounds), Usage, Agent usage and Caps, the theme and motion notes, and the proposal card's "what applying does".
- **Edit links land through the route.** `#/settings/connections/<name>`, `#/settings/dossiers/<dossier>/<section>` and `#/settings/agent-usage/caps` (`ui/src/format.ts`). The page focuses and scrolls to its target once it has loaded (`useLandOn`); the app skips its usual heading focus for those routes so the two don't race. A target that's gone (a removed connection or dossier) is said on the page.
- **Where pencils are:** an item's connection and its fields, a dossier's sources (card and dashboard), the People view's people and work-in-progress limit, an assignment's adapter, and a cap notice under an answer and an assignment's limits form. The adapter's name in the Ask strip already has the agent switcher and the strip's (i) links to Settings, Agent, so it got none.
- **Help in the header links to the current view's docs section** (`viewHelpHref`), and on a settings page to that page's section. It opens the site in a new tab, the same as Read more.
- **The Ask bar's placeholder has a short form on a narrow screen** (`ask.placeholder.short`, below 600px): at 375px Realm's "Petition the steward about card-payments" was cut off, so narrow screens say what to do and leave the dossier's name to the page. Each game theme has its own short form.
- **The layout check opens a help tooltip on People, Connections and General, and a help popover on those and the dashboard.** On CI's Linux runner the dashboard's tooltip state failed at 768 and 1440px only, after the width before had opened and closed its Assign dialog and Ask view; it passed every local run on Windows. Rather than chase the runner's focus timing, the dashboard keeps its popover state and drops the tooltip one: it is the same component, and its tooltip is checked in the other three views at every width and theme, and in `ui/test/help.test.tsx`.
