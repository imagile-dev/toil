# The feedback form's address, in one place (#435)

- **The constant is the existing `FEEDBACK_FORM` in `src/feedback/consent.ts`**, now `https://imagile-dev.github.io/toil/about/feedback/`. It already held the form's address for `toil feedback`'s fix text, and it sits beside the disclaimer that `test/feedback-consent.test.ts` holds every copy to. No second constant for the path alone: the tests and the link check take the path from the URL.
- **Toil UI imports it by relative path** (`ui/src/feedback.ts` from `../../src/feedback/consent.ts`), the way `ui/src/fixtures/feedback.ts` already imports `DISCLAIMER` and `FEEDBACK_ENDPOINT`. It isn't added to `@imagile-dev/toil/api`: the page is a browser bundle that compiles toil's sources, and the API's exports are part of the command contract.
- **Markdown can't import a constant**, so `skills/toil/core.md` and `ui/docs/themes.md` spell the address out, and `test/feedback-consent.test.ts` fails if either lacks `FEEDBACK_FORM` or names any other feedback address on the site.
- **Two checks, not one.** `site/scripts/check-links.mjs` holds `FEEDBACK_FORM` to the built site (a page the build made, not an old address that forwards), importing `consent.ts` the way `check-help-links.mjs` imports `ui/src/help.ts`. The site builds only on PRs that touch `site/` or `ui/` (`pages.yml`), so `test/feedback-consent.test.ts` also holds it to the site's page sources and `REDIRECTS` on every PR. The workflow's path filter is left alone, keeping the change out of `.github/`.
- **The `/feedback/` redirect stays** in `site/src/lib/redirects.mjs`, as the issue asks. Site pages are untouched.
- **The Feedback dialog's notes wrap anywhere** (`.feedback-body p { overflow-wrap: anywhere; }` in `ui/src/feedback.css`). The longer address made the sample's "Sending is turned off" note 12px wider than a 375px phone in Harvest, whose font is wider; the smoke's layout check caught it. Wrapping inside the URL beats shortening the copy or naming the form without its address.
