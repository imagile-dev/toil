# Toil UI's agent features, run live on GitHub Copilot (#317)

- **Copilot ran on `mai-code-1.1-flash`, the cheapest model the account lists.** No model was at 0×; the list was `auto`, `claude-sonnet-4.6` (9×), `claude-haiku-4.5` (0.33×), `gpt-5.3-codex` (6×) and `mai-code-1.1-flash` (0.25×). Every answer and usage record was checked for that model, and none named another. The README says how to pick the cheap model for each adapter.
- **Copilot's premium requests are counted once per prompt, on the call whose `initiator` is `user` (or absent).** Every `assistant.usage` event reports the model's multiplier as `cost`, the agent's own follow-up calls in the tool loop included, but the session's `usage.getMetrics` billed one multiplier per prompt (three calls, each `cost: 0.25`, billed `0.25`). Summing every call overstated a question 3 to 6 times, and the per-chat premium cap stopped an assignment at "0.5" after Copilot had billed 0.25. The follow-up calls now report 0 premium requests rather than leaving the figure out, because the SDK did report them, at no charge.
- **A Stop is reported as a stop.** A person's Stop reached the worklog as "GitHub Copilot failed: The question was stopped. Check that the Copilot CLI is signed in". The host now says the adapter was stopped before it finished, for every adapter, whatever the SDK threw on the way out. Assignments keep their own stop reasons (time limit, cancelled), which the queue sets before this text is seen.
- **An investigation on a GitHub item proposes `github pr comment`.** The report's comment proposal knew only Jira and Azure DevOps, so on a GitHub dossier it had no command, though toil comments on an issue by its number with `github pr comment` (`issue comment` on the CLI). Its input is the number and the body, and the dossier supplies the owner and repository, as it does for the agent's own GitHub proposals.
- **`verify:ui --ask` takes `--adapter` and `--model`.** The same checks Codex gets now apply to Copilot and Claude (Codex is the reference), with Codex's MCP-server check skipped for the in-process adapters, and the run fails when an answer or a usage record names a model other than the one asked for. The root script now forwards its arguments with `--`, because npm read `--adapter copilot` as its own config and the first run quietly asked Codex instead.
- **`dev-real.mjs` reads Claude Code's sign-in and never refreshes it.** The scratch home hides `~/.claude`. Pointing `CLAUDE_CONFIG_DIR` at a copy or a link of the credentials would let Claude Code refresh, and so rewrite or rotate, the person's real credentials. So a `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY` in the shell is used as it is, and otherwise the unexpired access token in `~/.claude/.credentials.json` goes to Toil UI's environment as `CLAUDE_CODE_OAUTH_TOKEN`, which Claude Code uses without refreshing. When it has expired the script says so and names the two fixes.
- **The rest of the live run is scratch tooling, not a committed script.** Assignments, Stop, caps, stale sessions and notifications were driven through Toil UI's own HTTP API and the browser; the transcripts are under `ui/docs/live-runs/`. A committed driver would be a second test harness for features `verify:ui` and the unit suite already cover.
