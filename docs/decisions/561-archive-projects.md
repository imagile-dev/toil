# Archive and unarchive Toil projects (#561)

- **Archiving only hides; it never changes resolution.** `archived: true` in the person's own file leaves `toil projects list` (unless `--all` or `--archived`), Toil UI's list, switcher and sync (which read `projects list`), and nothing else. A folder in an archived project's repo still resolves to it, so a call never quietly loses its inputs (the fall-through that #540 closed). Skipping archived projects in area-context resolution would be a behaviour change a person didn't ask for; if it is wanted later it is its own decision.
- **Additive, not breaking (principle 7).** A new optional `archived` key, two new commands, two new `list` flags and new `data` fields (`archived` per project, `archivedHidden`). One consequence: `projects list` without a flag now omits archived projects, which only exist once someone archives one. An older toil reading such a file warns about an unknown `archived` section and lists the project normally.
- **Archive and unarchive are local writes, not deletes, so both are MCP tools.** They follow `projects describe`: `writesLocal`, no `--allow-write`, your own folder only, with the `projects import` fix for a checked-in or listed project. Asking twice returns `changed: false` and writes nothing.
- **`projects list` says what it hid.** `archivedHidden` counts the archived projects a plain list left out (0 under `--all` and `--archived`), so a caller can tell "none" from "hidden" (principles 4 and 12). `--all` and `--archived` together are `INVALID_INPUT`.
- **Sharing drops the flag.** `projects export` writes the project without `archived`: archiving is your own tidying, and a teammate importing the file starts with it open.
- **Toil UI reads the archived list with `projects list --archived`.** If that call fails (a toil too old for the flag) the list is `null`, the "Archived (n)" disclosure is not drawn, and the failed call is left out of Sources. Unknown is not zero. A real zero draws nothing either, since there is nothing to open.
- **Three ways in, one way back (principle 11).** A card's "more" menu (the only addition to a card), the command palette (found by typing "archive" or a name, kept out of the empty palette), and Settings, Toil projects (the same menu on each of your own projects). Undo is one line under the header with an Undo button; it clears when the page changes. Unarchive is in the disclosure, the palette and the undo line.
- **Not done:** Archive on the dashboard header (the file is off limits in this slice), and a stronger confirmation. Archive is one press and reversible, so it asks nothing.
