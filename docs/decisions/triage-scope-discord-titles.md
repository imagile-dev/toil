# Triage fixes almost anything, and Discord posts the real title (no issue)

- The scope is a short refusal list instead of an allowlist (`scripts/triage/changes.mjs`). Triage's own rules (`.github/`, `scripts/`, `CLAUDE.md`, `.claude/`, `AGENT_DECISIONS.md`, `docs/decisions/`, `dist/`) stay refused under principle 2; so do `package.json` and every lockfile (the agent has no npm, so no 14-day check), and the site and the Azure Function backend, which are a `maintainer` decision, not an edit. Open: `src/`, `test/`, `docs/`, `skills/`, `README.md`, and `ui/` with its old exclusions.
- Any other file at the repository root, and any dot-folder, is refused too. The maintainer named the refused paths, not these, but a triage fix that edits `tsconfig.json`, `.npmrc` or `release-please-config.json` is build and release plumbing like the lockfile. It is one line in `OPEN_ROOT_FILES` to relax.
- `docs/decisions/**` is refused whole, including the PR's own file. The draft's description carries the agent's reasoning, and the agent can't know its branch number to name the file.
- A new area under `src/areas/<new>/` is not refused. It is under `src/`, so the rule lets it through. The prompt doesn't treat it as maintainer work; the Authentication Bar still binds, and a denial would quote it.
- `maintainer` leaves the issue open and labels it `needs-maintainer`; `apply` comments and labels, and closes nothing. A later re-triage is manual, as for any open issue; no label removes `needs-maintainer` automatically.
- The areas a fix touched are reported by `check()` as a sorted list, not a single area. `archive.mjs` and `changes.mjs`'s CLI print them comma-separated, or `-` when none.
- Safety layer in core is by file name in `src/core/` (the write gate and `run`, call and area resolution, dossier adoption, the credential store and secret input, files, git, network and request hosts, bounds, audit, config), each with its test, plus `src/os/`, `src/shims/`, `src/mcp/`, `src/api.ts`, `src/node-context.ts`, `src/program.ts`, `docs/bounds.md`, `test/bounds.test.ts` and `test/parity.test.ts`. A hand-kept list goes stale when a core file is added; the failure mode is a missed flag, not a missed refusal, and review reads the diff anyway.
- A change to core adds a line to the draft PR saying CI's full gate has to be green first, next to Toil UI's existing one.
- Discord: the redacted title is posted by `node scripts/triage/redact.mjs --title` (title and `REDACT_TERMS` in env, never argv), run from `main`'s checkout. The title is folded to one line and cut to 200 characters. If the redactor fails or returns nothing, the post says "title withheld" rather than the original, because the safeguard is the point. The job checks out `main` for every issue, insiders' included, which costs a few seconds; a conditional checkout would make the YAML more than wiring.
