# Toil UI syncs Jira Cloud dossiers, and triage may change Toil UI (#487)

- The sync table in `ui/server/sync.ts` already knew `jira-cloud issue search` and `history`; the missing branch was the loader (`ui/src/load.ts`), which asked `areas.jira` only. It now loops over `JIRA_AREAS` (`jira`, `jira-cloud`), the way `ADO_AREAS` does for Azure DevOps. A dossier with both sections reads both, each under its own area.
- `READ_COMMANDS` (the Store's allowlist) and `LIVE_COMMANDS` (the agent's live reads) gained the Cloud commands. Without the first, a cached dossier could not serve the Cloud reads at all.
- Coverage is a Jira Cloud variant of card-payments built in `ui/test/registry.test.ts`, not a fourth sample dossier: a new sample would change every screen, the showcase and the screenshots for a test's sake. Its calls are held to the real registry and loaded end to end.
- Triage scope: Toil UI is `ui/src/`, `ui/docs/`, `ui/test/`, `ui/themes/` (CSS and raster images; not `theme.json`, whose `voice` is prompt text for Toil UI's agent, and not SVG, which can carry script) and `ui/server/reads.ts`. The rest of `ui/server/` is Toil UI's core (launch token, CSP, write gates, env and tool allowlists, spawning), so it stays maintainer work, as `src/core/` does for areas; so do the suites that hold Toil UI to its rules (`registry`, `themes`, `package`, `install` tests, `setup.ts`, `harness.ts`, `config.test.ts`), `ui/src/config.ts` (the Settings write allowlist, `CONFIG_COMMANDS`), `ui/package.json`, build and lint configuration and `ui/scripts/`. Both reviews found the first draft (all of `ui/server/` but `install.ts`) too wide: a fix could change what Toil UI spawns without importing `child_process`. The read list lives in its own data-only `ui/server/reads.ts` so a new read command can be added there while `store.ts`, which holds the read-only lock (`toilOptions`), stays maintainer work. Modules the server imports from `ui/src/` (the worklog export name, the write proposals a person presses, usage settings) stay in scope with the rest of `ui/src/`: the sync runs read-only, file access stays in the workspace, writes need the connection's `writes` plus `--allow-write`, and a human merges the draft. Refusing them was weighed and not done, because it would carve most of `ui/src/` out for the sake of a few modules. The review bot raised both points; the line is the maintainer's to confirm.
- One area plus Toil UI in the same fix is allowed, because a Cloud-variant bug often spans a command and its screen; two areas stay refused. The enforcement is `scripts/triage/changes.mjs`, not only the prompt, since a prompt is a request.
- A fix that touches `ui/` gets a paragraph in its draft PR saying it needs `npm run verify:ui` and the screen review, because the agent cannot run either.
