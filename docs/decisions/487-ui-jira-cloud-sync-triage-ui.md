# Toil UI syncs Jira Cloud dossiers, and triage may change Toil UI (#487)

- The sync table in `ui/server/sync.ts` already knew `jira-cloud issue search` and `history`; the missing branch was the loader (`ui/src/load.ts`), which asked `areas.jira` only. It now loops over `JIRA_AREAS` (`jira`, `jira-cloud`), the way `ADO_AREAS` does for Azure DevOps. A dossier with both sections reads both, each under its own area.
- `READ_COMMANDS` (the Store's allowlist) and `LIVE_COMMANDS` (the agent's live reads) gained the Cloud commands. Without the first, a cached dossier could not serve the Cloud reads at all.
- Coverage is a Jira Cloud variant of card-payments built in `ui/test/registry.test.ts`, not a fourth sample dossier: a new sample would change every screen, the showcase and the screenshots for a test's sake. Its calls are held to the real registry and loaded end to end.
- Triage scope: all of `ui/` except `ui/server/agents/install.ts` (the one file that spawns), Toil UI's `package.json`, lockfile and build configuration, and `ui/scripts/`. This is the maintainer's choice (#487, 2026-10-26, asked directly), made after reviews of this PR proposed narrower rules: `ui/server/reads.ts` alone, no `ui/src/config.ts`, no `theme.json` or SVG, no gate suites. Their point stands: a triage fix may now edit Toil UI's safety layer (the launch token, CSP, write gates, read list and read-only lock, agent tool and env allowlists and launchers, Settings' write allowlist, the `READ_COMMANDS` pin). So the edit is made visible instead: `SAFETY_LAYER` in `scripts/triage/changes.mjs` lists those files, `open-pr` puts the list at the top of the draft's description (computed from the checked paths, so the agent can't leave it out), the agent must say what each edit loosened or widened, and the review prompt asks for the same opening paragraph. The read list stays in its own data-only `ui/server/reads.ts`, split from `store.ts` which holds the read-only lock, so a new read touches one small file.
- One area plus Toil UI in the same fix is allowed, because a Cloud-variant bug often spans a command and its screen; two areas stay refused. The enforcement is `scripts/triage/changes.mjs`, not only the prompt, since a prompt is a request.
- A fix that touches `ui/` gets a paragraph in its draft PR saying it needs `npm run verify:ui` and the screen review, because the agent cannot run either.
