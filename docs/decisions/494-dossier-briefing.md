# The dossier briefing, by code (#494)

- `toil dossiers brief` takes Open Work Item records from stdin, `--input-file` or `--text`, and contacts no service. Gathering the dossier's items and pull requests is left to the caller (`<tracker> … | util owi map`), so one command doesn't decide which services to ask (principle 3). It reads the dossier for its settings: only `wipLimit` in this slice, and the `analyze` key in slice 2.
- The lenses are computed from OWI fields alone: failing checks and review waits from a pull request's `checks`, `checksAt`, `created` and `firstReviewAt`; blocked from `blocks` links; stale from `updated`; load from `assignee` and `wipLimit`; drift from a pull request's state against its item's. Builds and deployments, which Toil UI reads from Jenkins, Azure Pipelines and OpenShift, aren't OWI yet, so "failing" here means a pull request's checks, not a pipeline run. Toil UI's per-card insights keep using its builds and deployments.
- Readiness stays off in the standard lenses and isn't computed by toil: the readiness checks live in Toil UI. The result lists it under `lenses` as not checked.
- An item goes under the first lens in the dossier's order that flags it, so it appears once. Done items are counted as on track, except under drift, where "done while its pull request is open" is the point.
- Within a reason, items holding up the most open work come first (`holds`, counted down `blocks` chains), and the first reason's first item becomes the recommendation. A plain template per lens writes the recommendation; Analyze (slice 2) writes a better one.
- The sprint is the iteration most open items are in, by its dates or the tracker's `current`. Its pace isn't judged until a quarter of it, and at least a working day, has gone, because stories finish late in a sprint. The sandbox's Sprint 43, one day in with nothing done, read as "none land at this pace" before this rule.
- Default thresholds: failing checks after 4 hours, a first review after 2 working days (Toil UI's existing `PICKUP_DAYS`), stale after 5 days (Toil UI's existing `STALE_DAYS`), drift after a merge more than a working day old. Toil UI now reads the first two from toil's lens definitions, and its `workingDays` from `src/core/brief/time.ts`, so the CLI and Toil UI count the same days.
- The parity suite's fixture for commands outside an area now holds one workspace file, `owi/brief.owi.json`, so an example covers `--input-file`.
- The welcome menu's Briefing view isn't in this PR. Gathering a dossier's items in the terminal needs the per-area reads Toil UI's `load.ts` makes, and toil can't import from `ui/`. Where that shared reader belongs is the maintainer's call (raised on the session, 2026-10-27).
