# A new site map: Connect, regrouped docs, About (#431)

- **Docs pages keep their addresses.** The issue regroups the docs as a path; it doesn't move them, and Toil UI's Read more links (`ui/src/help.ts`) point at `/docs/ui/`, `/docs/core/`, `/docs/dossiers/` and `/docs/themes/`. Only the pages the issue names moved: `/integrations/` → `/connect/`, `/docs/integrations/<area>/` → `/connect/<area>/`, `/docs/databases/` → `/connect/db/`, `/how-it-works/`, `/principles/` and `/feedback/` → `/about/…`.
- **The databases are one page, `/connect/db/`, with each engine a tile on `/connect/` linking to its section of `db.md`.** `db.md` is one file with a section per engine (two engines share Hive and Impala's), and splitting it into eight pages would split the skill file agents read. Each engine's level comes from its provider (`site/src/data/databases.json`, written by `test/site-commands.test.ts`), and its sign-in and section from `site/src/data/db-sign-in.json`, which the same test holds to the providers' engine list.
- **New categories for the integrations:** Work tracking, Source and review, CI/CD and runtime, Testing and flags, Security and quality, Observability, Docs and design, with Databases third. Azure DevOps (boards, repos and pipelines) is under Work tracking, where its work items put it first; Artifactory is under CI/CD.
- **Redirects are static pages from one list.** `site/src/lib/redirects.mjs` lists every old address; `site/src/pages/[...old].astro` builds a page at each that forwards with its query and hash (`location.replace`), with a meta refresh and a link without script. They're left out of the sitemap and marked `noindex`. `/ui-preview/`'s forward moved onto the same list.
- **A link check runs after every build** (`site/scripts/check-links.mjs`): every internal link and anchor on every built page resolves, no page links to an old address, and every old address forwards to a page that exists. The issue asks for no broken internal links, and nothing checked that before beyond the help links.
- **The link check reads only site-relative links.** A page that links to its own site by full URL (`ui/docs/themes.md`'s feedback link, rendered on `/docs/themes/`) isn't checked, so a full-URL link to an old address passes; it still forwards. Checking full URLs would mean editing `ui/docs/themes.md` here, which other open PRs edit.
- **`toil feedback`, Toil UI and the shipped skill still name `/feedback/`.** It forwards to `/about/feedback/`, and changing those strings would change the published CLI and Toil UI packages (and `ui/docs/themes.md`, which other open PRs edit) for no gain to the reader. Repository docs (`README.md`, `.github/`, `docs/integrations.md`) use the new addresses.
- **The not-planned list is gone from `docs/integrations.md` too**, not only the site: the maintainer asked for no list of what isn't planned.
- **The home page keeps its hero as is**, marked as the slot #432's map fills, and drops the integrations ticker, the stats, the token-efficiency section, the envelope demo, the locked-down section, the MCP stand-in, the feedback panel and the closing call to action. All but the ticker, the stats and the call to action moved to `/about/`, under the four About pages; the hero's **See it work** now opens `/about/#demo`. The Connect section keeps the switchboard art and one link with both counts.
- **`/map/` is a placeholder** that says the map is coming and links to Connect and the docs, so the nav's first link has a target until #432.
- **`/about/changelog/` renders `CHANGELOG.md`**, which release-please writes, so the site keeps no copy.
- **A command index, `/docs/commands/`,** lists every command from the registry's generated lists (`site/src/data/commands/*.json`), for the Reference group. `test/site-docs.test.ts` holds it to the prose rule and exempts it from rendering a skill file.
- **The docs index shows the path's page names without their descriptions**, three groups across on a desktop, before `SKILL.md`'s own index. With the descriptions it was most of a screen per group, and each page's hero says what it is.
- **Command names on the area pages read `toil jira issue get` again.** The commands list ran the area and the command together (`toil jiraissue get`): two adjacent expressions in the template lost the space between them. It is one template string now (`site/src/components/CommandIndex.astro`). Found in this PR's screenshots; it was live on the site before.
- **The before and after excerpts on `/about/` are focusable regions.** axe flagged them (`scrollable-region-focusable`) once they moved; they had the same problem on the home page.
